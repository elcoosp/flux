## Working today

- **Dev server (`flux dev`)** — binds a WebSocket on `:7331` and an HTTP asset
  server on `:7332` (with a `/health` probe). Saves are diffed and shipped as
  binary patches to the host. Verified live against `examples/counter`.
- **Host apps (iOS & Android)** — precompiled native hosts that connect to the dev
  server, run the embedded bytecode VM, and reconcile a shadow tree of native views.
  Default connection is `ws://127.0.0.1:7331`.
- **CLI (`flux init` / `flux dev` / `flux build` / `flux doc`)** — scaffold,
  serve, and codegen projects.
- **Release codegen (`flux build ios` / `flux build android`)** — lowers `.flux` to
  idiomatic SwiftUI / Jetpack Compose source (see the
  [Counter example](/guides/counter-example/)).

## In progress

- **Host↔server reconcile parity gate (ADR-0027)** — the Swift and Kotlin hosts
  must produce byte-identical reconcile traces. The golden scenarios
  (`counter_1000`, `noop_dispatch`, `pure_subtree`, `cond_flip`,
  `unrelated_signal`) are defined; the CI badge below flips to green when the
  `flux-parity` tool runs them both and they match.

## What "state" means here

State is [host-authoritative](/concepts/host-authoritative-state/): the server ships
structure and deltas, the host owns the signal graph. That is why a 1,000-node tree
costs **one update** when you tap a counter bound to a single signal — independent
of tree size.

## Architecture decisions

Every non-obvious choice is recorded as an ADR in the repo under
[`docs/adr`](https://github.com/flux-lang/flux/tree/main/docs/adr). They are not
copied into this site to keep it fast and focused on getting you running.
