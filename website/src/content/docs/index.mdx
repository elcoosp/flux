## Get it running in 5 minutes

```bash
# 1. Build the CLI
cargo build --bin flux            # produces target/debug/flux

# 2. Scaffold a project
flux init myapp && cd myapp

# 3. Start the dev server (WebSocket on :7331, HTTP assets on :7332)
flux dev

# 4. Open the host app on iOS or Android and point it at ws://127.0.0.1:7331
```

The full walkthrough — including how to build and run the iOS and Android host
apps — is in the [Quickstart](/guides/quickstart/).

## How a tap becomes pixels

<Steps>

1. **Dispatch** — a `Button` tap evaluates its handler closure in the host VM,
   writing one or more signals (e.g. `count = count + 1`).

2. **Signals** — the VM reports the written signal ids, sorted ascending.

3. **Dirty set** — the host intersects the written signals with each node's
   `signal_deps`, emitting a `dirty` list in `(depth asc, id asc)` order.

4. **Update** — only the dirty nodes re-materialize their props and fire
   `update`. Clean siblings are untouched.

5. **step_end** — cumulative counters close the step: `built`, `updated`,
   `skipped_unchanged`, `detached`, `prop_materializations`.

</Steps>

On release builds this same component is codegen'd to native code — see the
[Counter example](/guides/counter-example/) for both the Swift and Kotlin output.
