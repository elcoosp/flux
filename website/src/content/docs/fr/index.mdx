## Comment un tap devient des pixels

<Steps>

1. **Dispatch** — un tap `Button` évalue la closure de son handler dans la VM hôte,
   écrivant un ou plusieurs signaux (ex. `count = count + 1`).

2. **Signals** — la VM rapporte les ids de signaux écrits. Selon l'ADR-0027 ils sont
   triés ascendants et émis comme événement de trace `signals`.

3. **Dirty set** — l'hôte intersecte les signaux écrits avec le `signal_deps` de
   chaque nœud (Phase 2) ou ré-applique à bas coût (Phase 1), émettant une liste
   `dirty` dans l'ordre `(depth asc, id asc)`.

4. **Update** — seuls les nœuds sales re-matérialisent leurs props (≤ 2
   matérialisations, sur changement réel) et déclenchent `update`. Les frères
   propres sont intacts — `skip_unchanged`.

5. **step_end** — les compteurs cumulatifs ferment l'étape : `built`, `updated`,
   `skipped_unchanged`, `detached`, `prop_materializations`.

</Steps>
