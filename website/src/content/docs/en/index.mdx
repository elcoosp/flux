## How a tap becomes pixels

<Steps>

1. **Dispatch** — a `Button` tap evaluates its handler closure in the host VM,
   writing one or more signals (e.g. `count = count + 1`).

2. **Signals** — the VM reports the written signal ids. Per ADR-0027 they are
   sorted ascending and emitted as a `signals` trace event.

3. **Dirty set** — the host intersects the written signals with each node's
   `signal_deps` (Phase 2) or re-applies cheaply (Phase 1), emitting a `dirty`
   list in `(depth asc, id asc)` order.

4. **Update** — only the dirty nodes re-materialize their props (≤ 2
   materializations, on genuine change) and fire `update`. Clean siblings are
   untouched — `skip_unchanged`.

5. **step_end** — cumulative counters close the step: `built`, `updated`,
   `skipped_unchanged`, `detached`, `prop_materializations`.

</Steps>
