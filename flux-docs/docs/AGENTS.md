# AGENTS.md — Flux documentation site

This repository is the standalone Starlight documentation site for the Flux
UI language ([elcoosp/flux](https://github.com/elcoosp/flux)). It documents
the project; it does not contain the project.

## What this site is

- **Framework:** Astro 7.4.x + Starlight 0.42.x (version floor — never ship
  lower), pnpm as the package manager of record.
- **TypeScript:** pinned to `6.0.3` exactly. `astro check` does not support
  TypeScript 7; see `docs/decisions/0001-typescript-version.md` before
  touching the pin.
- **Search:** Pagefind (bundled with Starlight). No DocSearch application
  exists; do not add one without an approved Algolia app.
- **Search index:** `dist/llms.txt` + `dist/llms-full.txt` are generated by
  `scripts/generate-llms.mjs` at the end of `pnpm build`.

## Layout

```
src/content/docs/
├── index.mdx          # splash landing (type: explanation)
├── tutorials/         # learning-oriented, guided end to end
├── guides/            # task-oriented how-tos
├── reference/         # information-oriented, tables and exact surfaces
└── explanation/       # understanding-oriented
```

## House rules

1. **Diátaxis, one type per page.** Every page carries
   `type: tutorial | how-to | reference | explanation` in frontmatter; the
   content schema (`src/content.config.ts`) enforces it, and a page that
   mixes types is wrong by definition. Split mixed pages instead of bending
   the type.
2. **Never invent.** Document only what exists in the Flux repository:
   verify commands, flags, props, opcodes, and ids against the source
   (`crates/flux-cli/src/lib.rs`, `stdlib/*.flux`,
   `docs/spec/mlp-appendices.md`) before writing them. Cite ADR numbers for
   non-obvious decisions.
3. **Writing standards.** Second person, present tense, active voice,
   imperative instructions. Never use "simply", "just", "easy", or
   "obviously". Every code block has a language tag. Every page ends with
   next-step links.
4. **Reference pages use tables.** Signature, type, default, required?,
   description, example — a table row per item.
5. **Sidebar order is frontmatter order.** `sidebar.order` inside a section
   directory controls position; autogenerate picks it up.
6. **Internal links must resolve.** `starlight-links-validator` fails
   `pnpm build` on broken internal links — that is a release blocker, not a
   warning.
7. **Both themes.** Verify changes in light and dark mode; the accent
   palette lives in `src/styles/custom.css` and passes WCAG AA (see
   `docs/decisions/0003-brand-accent.md`).

## Commands

| Command | Action |
| :--- | :--- |
| `pnpm install` | Install dependencies |
| `pnpm dev` | Dev server at `localhost:4321` |
| `pnpm build` | Production build to `dist/` + generate llms.txt |
| `pnpm preview` | Preview the built site |
| `pnpm check` | `astro check` (TypeScript diagnostics) |
| `pnpm lint` | `markdownlint-cli2` over `src/content/docs` |
