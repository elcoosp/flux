# 1.0 Evidence Checklist (FLUX-069 / PRD-U §13)

The roadmap §1 defines 1.0 as **five evidence criteria**. This checklist is the
human-evidence half of the release gate (the machine-enforced half is
`RELEASE-GATE.md` + `release-gate.yml`). The `v1.0.0` tag is cut only when every
box below is checked **with evidence linked** — not when the feature list is
full.

> Process gate: dogfood + closed-beta + bug-bash evidence cannot be produced
> in-repo. This file is filled by the release manager as that evidence arrives;
> the CI contract-freeze job (machine half) is a *prerequisite*, not a
> substitute.

## Criterion 1 — 90% use-case coverage
- [ ] A typical CRUD / social / e-commerce app builds without dropping to native
  code (forms, lists, media, navigation, auth, networking, push, offline cache,
  animations), except documented exotic integrations.
- [ ] Evidence: `docs/release/top-20-patterns.md` coverage table — all 20
  covered without a WebView escape hatch.

## Criterion 2 — 10x DX (measured, not asserted)
- [ ] Inline `.flux`-source diagnostics in the editor (LSP).
- [ ] On-device error overlay with real stack trace back to source.
- [ ] Hot-reload state preservation survives structural edits (`Patch::Reattach`).
- [ ] Closed-beta median **time-to-diagnose** and **time-to-fix** vs a matched
  RN/Flutter cohort, published.
- [ ] Evidence: `docs/time-to-feature-report.md` (beta-tracked, RN/Flutter
  cohort comparison).

## Criterion 3 — DevTools parity+ (ship it, not scaffold it)
- [ ] Component tree, signal graph, timeline/flamegraph, network inspector,
  time-travel debugging each shipped and demoed.
- [ ] Evidence: `flux-devtools-ui` feature checklist; demoed against a running
  app (FLUX-062 on-device verification).

## Criterion 4 — Verified performance budget
- [ ] §3.10 budgets (native mutation < 3 ms, save→pixels < 100 ms p99) measured
  on **both** platforms in CI.
- [ ] Cold start, hot-reload latency, release binary size published vs RN/Flutter.
- [ ] Evidence: `perf-harness.yml` MetricRecord JSON + `benchmarks.yml`
  save-photon gate (both green in the release-gate run).

## Criterion 5 — iOS/Android architectural parity
- [ ] ADR-0048 decision **closed** with data (one render tier, or a formally
  ratified permanent asymmetry).
- [ ] Evidence: ADR-0048 conclusion + both hosts rendering the same component
  vocabulary (§0.2 unified tier).

## Contract freeze (machine prerequisite)
- [x] `wire` protocol version frozen & consistent across server + both hosts
  (`docs/release/contract-versions.toml`, enforced by `release-gate.yml`).
- [x] `adapter` contract version frozen & consistent across both kits.
- [ ] `pin = "v1.0.0"` set in `contract-versions.toml` once RC is cut.
